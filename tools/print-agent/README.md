# ایستگاه چاپ فروشگاه — راهنمای نصب

## این چیست و چرا این‌طوری کار می‌کند؟

سایت شما روی اینترنت است و پرینترها داخل دفتر و انبار. سایت نمی‌تواند
مستقیم به پرینتر وصل شود، چون پرینترها پشت مودم و شبکهٔ داخلی هستند.

راه‌حل رایج این است که روی مودم پورت باز کنند — که هم دردسر دارد (IP ثابت،
تنظیم مودم) و هم پرینترهایتان را در معرض اینترنت می‌گذارد.

این برنامه برعکس عمل می‌کند: **خودش هر چند ثانیه از سایت می‌پرسد «کار چاپی
داری؟»** پس هیچ پورتی باز نمی‌شود و هیچ IP ثابتی لازم نیست. اگر اینترنت دفتر
قطع شود، کارها در صف سایت می‌مانند و به‌محض وصل شدن چاپ می‌شوند.

```
مدیر در پنل «چاپ» می‌زند
        ↓
کار در صف سایت می‌نشیند
        ↓
برنامهٔ پایتون (دفتر یا انبار) کار را برمی‌دارد
        ↓
صفحه را می‌گیرد → PDF می‌سازد → به پرینتر می‌فرستد
        ↓
نتیجه به سایت گزارش می‌شود → مدیر می‌بیند چاپ شد یا خطا خورد
```

هر کامپیوتر یک **ایستگاه** است. می‌توانید چند ایستگاه داشته باشید — مثلاً
«دفتر»، «انبار»، و «کامپیوتر خودم» — و مدیر هنگام چاپ انتخاب کند کجا چاپ شود.

---

## بخش ۱ — کارهای سمت سایت (یک بار)

۱. فایل‌های نسخهٔ تازه را آپلود کنید.
۲. یک بار `upgrade.php` را باز کنید تا جدول‌های `print_stations` و
   `print_jobs` ساخته شوند، سپس حذفش کنید.
۳. به **پنل مدیریت ← ایستگاه‌های چاپ** بروید.
۴. برای هر کامپیوتر یک ایستگاه بسازید (مثلاً «دفتر»).
۵. **توکن** آن ایستگاه را کپی کنید — در مرحلهٔ بعد لازمش دارید.

---

## بخش ۲ — نصب روی کامپیوتر دفتر یا انبار

### راهِ آسان (ویندوز): WebyPrint.exe — نسخهٔ ۲٫۰

1. در پنل، «ایستگاه‌های چاپ»، کنارِ ایستگاه **«⬇ دانلودِ برنامهٔ ویندوز»** را بزنید. یک ZIP می‌گیرید با
   `WebyPrint.exe` و `config.json` (نشانی سایت و توکنِ همان ایستگاه).
2. روی کامپیوترِ پرینتر ZIP را باز کنید (Extract) و روی `WebyPrint.exe` دوبار کلیک کنید و «Yes» بزنید.
   اگر ویندوز گفت «Windows protected your PC»: «More info» ← «Run anyway».
3. صفحهٔ تنظیمات (`http://localhost:8765`) خودش باز می‌شود؛ پرینترها را فعال کنید، کاغذ بگذارید، «چاپ آزمایشی».

پایتون، pip و هیچ نصبِ دیگری لازم نیست (همه داخلِ exe است). برنامه خودش را در `C:\ProgramData\WebyPrint` می‌گذارد،
در Task Scheduler ثبت می‌شود تا با ورودِ هر کاربر به ویندوز (در حسابِ همان کاربر — Edge در حساب SYSTEM اجرا نمی‌شود)
روشن شود و اگر بسته شد هر ۵ دقیقه دوباره بالا بیاید، در فایروال برای شبکهٔ داخلی (Private/Domain) پورت ۸۷۶۵ را باز می‌کند
و میان‌برِ «Weby Print Station» روی دسکتاپ می‌گذارد. **پورت همان ۸۷۶۵ است** و نصب آن را عوض نمی‌کند (ایستگاهِ Invora روی ۸۷۶۶ است؛
هر دو روی یک کامپیوتر کنارِ هم کار می‌کنند).

- نسخهٔ تازه: دوباره دانلود و اجرا — جایگزین می‌شود و پرینترها، کاغذها و تنظیمات می‌مانند.
- حذف: در Command Prompt ِ همان پوشه `WebyPrint.exe uninstall`
- گزارش‌ها: `C:\ProgramData\WebyPrint\agent.log` و `install.log`؛ آزمونِ کامل: `WebyPrint.exe selftest --out نتیجه.json`
- exe را GitHub Actions (`.github/workflows/print-agent.yml`) از همین `agent.py` می‌سازد، روی ویندوزِ واقعی نصب و حذفش را
  می‌آزماید و با نامِ انتشارِ `print-agent` می‌گذارد؛ پنل فقط با زدنِ دکمهٔ دانلود آن را می‌گیرد (نشانیِ دیگر:
  `define('WEBY_PRINT_EXE_BASE', 'https://…/')` در config.php).

### راهِ دستی (لینوکس، مک، یا ویندوز با پایتون)

### پیش‌نیازها

**پایتون ۳٫۹ یا بالاتر.** از [python.org](https://www.python.org/downloads/)
نصب کنید. در ویندوز حتماً موقع نصب تیک **«Add Python to PATH»** را بزنید،
وگرنه بعداً دستور `python` شناخته نمی‌شود.

**هیچ برنامهٔ جانبی لازم نیست.** روی ویندوز، برنامه صفحه را با Edge یا Chrome
به عکس تبدیل می‌کند و مستقیم با اندازهٔ واقعی روی پرینتر می‌کشد (از GDI خود
ویندوز). این روش برای برچسب دقیق‌تر هم هست، چون اندازه را خودمان بر حسب
میلی‌متر تعیین می‌کنیم.

SumatraPDF **اختیاری** است و فقط اگر بخواهید مسیر PDF را استفاده کنید لازم
می‌شود (مثلاً فاکتور چندصفحه‌ای A4). اگر نصبش کردید، برنامه خودکار پیدایش
می‌کند — حتی اگر فایلش را کنار `agent.py` بگذارید. روی لینوکس از `lp`
استفاده می‌شود.

### مراحل

پوشهٔ `print-agent` را روی کامپیوتر مقصد کپی کنید، بعد در همان پوشه
Command Prompt یا Terminal باز کنید:

```bash
pip install -r requirements.txt
python agent.py
```

همین. برای تبدیل صفحه به PDF هیچ نصب اضافه‌ای لازم نیست — برنامه خودش از
**Microsoft Edge** یا **Google Chrome** که روی ویندوز هست استفاده می‌کند.
هر ویندوز ۱۰ و ۱۱ از قبل Edge دارد.

> اگر قبلاً `playwright` نصب کرده‌اید و خطای
> «Executable doesn't exist» می‌گیرید، لازم نیست کاری کنید؛ برنامه خودکار
> سراغ مرورگر سیستم می‌رود. اگر می‌خواهید از playwright استفاده شود، یک بار
> `playwright install chromium` را اجرا کنید.

اگر همه‌چیز درست باشد، چنین چیزی می‌بینید:

```
============================================================
  ایستگاه چاپ فروشگاه — نسخهٔ 1.0
  رابط کاربری:  http://localhost:8765
  از شبکه:      http://<IP-این-کامپیوتر>:8765
============================================================
```

### تنظیم از طریق رابط کاربری

مرورگر را باز کنید و به `http://localhost:8765` بروید. از کامپیوترهای دیگر
همان شبکه هم می‌توانید با IP این کامپیوتر وصل شوید — مثلاً
`http://192.168.1.50:8765`.

**۱. اتصال به سایت.** نشانی API (`https://example.ir/print-api.php`) و توکنی
که از پنل کپی کردید را وارد و ذخیره کنید. چند ثانیه بعد چراغ بالای صفحه
سبز می‌شود و نام ایستگاه ظاهر می‌شود.

**چند سایت روی یک ایستگاه (نسخهٔ ۲٫۱).** یک ایستگاه می‌تواند به چند سایت
(چند فروشگاه Weby، یا حتی سایت Invora که پروتکل یکسان دارد) سرویس بدهد؛
لازم نیست برای هر سایت برنامه را جدا نصب کنید. در جدول «سایت‌هایی که به این
ایستگاه وصل‌اند» برای هر سایت نشانی API و توکنِ ایستگاهِ همان سایت را بنویسید
(سطر تازه با «+ سایت تازه»). هر سایت یک رشتهٔ جدا دارد: کارش با توکن خودش
گرفته می‌شود و نتیجه به همان سایت گزارش می‌شود؛ شمارهٔ کارِ دو سایت هم با هم
قاطی نمی‌شود. پرینترها و کاغذها مشترک‌اند و کارها یکی‌یکی چاپ می‌شوند.
برای هر سایت می‌شود نام، «چاپگر پیش‌فرضِ همان سایت» (وقتی کار چاپگر مشخصی
نخواسته)، خاموش/روشن و حذف را تعیین کرد؛ وضعیت اتصال و تعداد چاپِ هر سایت
کنارش دیده می‌شود. اگر `WebyPrint.exe` ِ ZIP سایتِ دوم را هم اجرا کنید، آن سایت
به **همین فهرست اضافه می‌شود** (سایت‌ها و کاغذ پرینترها پاک نمی‌شوند). فایل
`config.json` ِ قدیمی (فقط `api_url` و `token`) خودکار به `sites` منتقل می‌شود:

```json
{ "sites": [
    {"name": "فروشگاه", "api_url": "https://a.example/print-api.php", "token": "…", "enabled": true},
    {"name": "انبار",   "api_url": "https://b.example/print-api.php", "token": "…", "enabled": true, "printer": "Zebra"} ] }
```

**۲. کاغذ هر پرینتر.** فهرست پرینترهای این کامپیوتر خودکار پیدا می‌شود.
برای هرکدام مشخص کنید **الان چه کاغذی داخلش است** — یا از فهرست آماده
انتخاب کنید (A4، برچسب ۱۰×۱۵، حرارتی ۵×۳ و…) یا عرض و ارتفاع را دستی
بنویسید. یکی را هم پیش‌فرض کنید.

**۳. تست.** دکمهٔ «تست» جلوی هر پرینتر یک صفحهٔ آزمایشی چاپ می‌کند. تا وقتی
این کار نکرده، سراغ چاپ واقعی نروید.

## بخش ۳ — چطور جلوی چاپ روی کاغذ اشتباه گرفته می‌شود

این مهم‌ترین بخش است. هر کار چاپ، اندازهٔ کاغذ لازمش را با خودش می‌آورد —
مثلاً برچسب ۱۰×۱۵ یا فاکتور A4. قبل از چاپ، دو بار مقایسه انجام می‌شود:

**یک بار در سایت،** لحظه‌ای که مدیر دکمه را می‌زند. اگر کاغذ نخواند، همان‌جا
پیام خطا می‌بیند و کار اصلاً فرستاده نمی‌شود.

**یک بار در خود برنامه،** قبل از فرستادن به پرینتر. اگر نخواند، به‌جای چاپ
خراب، خطا به سایت برمی‌گردد و مدیر در فهرست کارها می‌بیند:

> کاغذ لازم ۱۰۰×۱۵۰ میلی‌متر است، اما در پرینتر «برچسب انبار» کاغذ ۲۱۰×۲۹۷
> میلی‌متر (A4) قرار دارد. کاغذ را عوض کنید و «تلاش دوباره» را بزنید.

**اغماض** (پیش‌فرض ۳ میلی‌متر) برای این است که اختلاف‌های جزئی اندازهٔ
برچسب‌ها مانع چاپ نشود. کاغذ چرخیده هم قبول می‌شود (۱۰۰×۱۵۰ با ۱۵۰×۱۰۰
یکی حساب می‌شوند).

> ⚠️ **هر بار کاغذ پرینتر را عوض کردید، در این صفحه هم به‌روزش کنید.**
> برنامه راهی برای فهمیدن خودکار کاغذ داخل پرینتر ندارد — فقط همین چیزی را
> می‌داند که شما گفته‌اید. اگر اینجا A4 نوشته باشد ولی برچسب گذاشته باشید،
> بدون خطا روی برچسب چاپ می‌کند.

## بخش ۴ — همیشه روشن نگه داشتن

برنامه باید همیشه در حال اجرا باشد، وگرنه کارها در صف می‌مانند.

**ویندوز — اجرای خودکار با روشن شدن.** یک فایل `start-print.bat` بسازید:

```bat
@echo off
cd /d "%~dp0"
python agent.py
```

کلید `Win + R` را بزنید، `shell:startup` را تایپ کنید، و یک میان‌بر از این
فایل داخل آن پوشه بگذارید.

**لینوکس — سرویس systemd.** فایل `/etc/systemd/system/weby-print.service`:

```ini
[Unit]
Description=Weby Print Agent
After=network-online.target

[Service]
ExecStart=/usr/bin/python3 /opt/print-agent/agent.py
WorkingDirectory=/opt/print-agent
Restart=always
RestartSec=10
User=YOUR_USER

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now weby-print
```

## بخش ۵ — عیب‌یابی

**چراغ سبز نمی‌شود.** توکن یا نشانی API اشتباه است. توکن را دوباره از پنل
کپی کنید (فاصلهٔ اضافی نداشته باشد). مطمئن شوید نشانی با `https://` شروع
می‌شود و به `/print-api.php` ختم می‌شود. اگر توکن را در پنل عوض کرده‌اید،
اینجا هم باید عوض شود.

**«هیچ پرینتری پیدا نشد».** در ویندوز یعنی `pywin32` نصب نشده — دوباره
`pip install -r requirements.txt` بزنید. در لینوکس یعنی CUPS نصب نیست:
`sudo apt install cups`.

**«SumatraPDF پیدا نشد».** نصبش کنید، یا اگر جای غیرمعمولی نصب شده، مسیر
کاملش را در `config.json` با کلید `sumatra_path` بگذارید.

**چاپ می‌شود ولی فارسی به هم ریخته یا برعکس است.** موتور را روی
«مرورگر سیستم» بگذارید — خروجی‌اش دقیقاً همان چیزی است که در مرورگر
می‌بینید. اگر playwright را ترجیح می‌دهید، مطمئن شوید `playwright install chromium` را اجرا
کرده‌اید. WeasyPrint در چیدمان راست‌به‌چپ ضعیف‌تر است.

**برچسب کوچک‌تر یا بزرگ‌تر از واقعیت چاپ می‌شود.** در تنظیمات درایور
پرینتر، مقیاس (Scale) را روی ۱۰۰٪ بگذارید و «Fit to page» را خاموش کنید.

**کار در حالت «دریافت شد» گیر کرده.** برنامه وسط کار بسته شده و هنوز چاپی
شروع نشده بود. بعد از ۵ دقیقه سایت خودش کار را به صف برمی‌گرداند، یا در پنل
«تلاش دوباره» را بزنید.

**کار در حالت «در حال چاپ» مانده و بعد «خطا» شده.** کاری که چاپش شروع شده،
هرگز خودبه‌خود دوباره چاپ نمی‌شود — چون شاید همان لحظه روی کاغذ آمده و
تکرارش یعنی یک برگ هدررفته. اگر ۲۰ دقیقه خبری از نتیجه‌اش نشود، سایت آن را
«خطا» علامت می‌زند و تصمیم با شماست: اگر روی کاغذ نیامده، در پنل «تلاش
دوباره» را بزنید. خودِ برنامه هم نتیجهٔ چاپ را چند بار پشت سر هم اعلام
می‌کند تا یک قطعی کوتاه اینترنت کار را ناتمام نشان ندهد.

## نکتهٔ امنیتی

توکن ایستگاه مثل رمز عبور است — هر کسی که آن را داشته باشد می‌تواند خودش را
جای این ایستگاه جا بزند و ببیند چه چیزی چاپ می‌شود. آن را در گروه‌های
تلگرامی و ایمیل نفرستید. اگر لو رفت، در پنل «توکن تازه» بزنید و در برنامه
هم به‌روزش کنید.

رابط کاربری این برنامه **هیچ رمزی ندارد** و برای شبکهٔ داخلی طراحی شده.
پورت ۸۷۶۵ را روی مودم به بیرون باز نکنید.

## انتخاب اینکه کدام پرینتر استفاده شود

در جدول پرینترها، ستون اول **«استفاده شود»** است. فقط پرینترهایی که تیک
می‌خورند برای چاپ به کار می‌روند؛ بقیه — حتی اگر روی ویندوز نصب باشند —
اصلاً استفاده نمی‌شوند.

- پرینتر تازه‌ای که به سیستم اضافه شود، **پیش‌فرض خاموش** است. این عمدی
  است تا چیزی ناخواسته روی پرینتر اشتباه چاپ نشود.
- اگر کاری برای پرینتر غیرفعال بیاید، به‌جای چاپ، پیام روشن می‌گیرید:
  «روی این کامپیوتر هست ولی فعال نشده».
- اگر هیچ پرینتری تیک نخورده باشد، هیچ کاری چاپ نمی‌شود و در گزارش
  می‌بینید که باید تیک بزنید.
- ردیف پرینترهای غیرفعال کم‌رنگ می‌شود و رادیوی «پیش‌فرض» برایشان
  غیرفعال است.
- اگر پرینتر پیش‌فرض را خاموش کنید، پیش‌فرض خودکار به اولین پرینتر فعال
  منتقل می‌شود.

| **چاپ مستقیم** | صفحه → عکس با Edge/Chrome → کشیدن روی پرینتر با اندازهٔ دقیق. بدون هیچ نصبی. بهترین گزینه برای برچسب |
| **از راه PDF** | نیازمند SumatraPDF؛ برای چاپ چندصفحه‌ای A4 مناسب‌تر است |

اگر مسیر PDF انتخاب شده باشد ولی SumatraPDF پیدا نشود، برنامه خودش به چاپ
مستقیم برمی‌گردد و در گزارش می‌نویسد.

جدا از این تنظیم کلی، اگر برای پرینتری در جدول پرینترها درایور
«TSPL حرارتی» انتخاب شده باشد، کارهای آن پرینتر همیشه از مسیر TSPL
می‌روند (بخش پایین را ببینید).

> **مهم:** تنظیم چرخش و اندازهٔ هر پرینتر **فقط در مسیر چاپ مستقیم** اعمال
> می‌شود. مسیر PDF کار را دست‌نخورده به SumatraPDF می‌دهد و آن‌ها را نادیده
> می‌گیرد. اگر روش چاپ را روی «از راه PDF» گذاشته باشید و چرخش تنظیم کرده
> باشید، برنامه در گزارش هشدار می‌دهد.

در گزارش، پای هر چاپ موفق می‌بینید که از کدام مسیر و با چه تنظیمی انجام شده،
مثلاً: «روی برچسب‌زن چاپ شد (چاپ مستقیم، ۵۰×۳۰ م‌م، چرخش ۹۰°)».

تراکم نقطهٔ عکس با کلید `render_dpi` در `config.json` قابل تنظیم است
(پیش‌فرض ۳۰۰). برای پرینترهای حرارتی ۲۰۳ نقطه، مقدار ۳۰۰ کیفیت خوبی می‌دهد.

## موتور تبدیل به PDF

| گزینه | توضیح |
|---|---|
| **خودکار** (پیشنهادی) | اول مرورگر سیستم، بعد playwright، بعد weasyprint |
| **مرورگر سیستم** | Edge یا Chrome خود ویندوز — بدون نصب، بهترین نتیجه برای فارسی |
| playwright | فقط اگر نصب و `playwright install chromium` اجرا شده باشد |
| weasyprint | روی ویندوز GTK لازم دارد؛ توصیه نمی‌شود |

اگر مرورگر در مسیر غیرمعمولی نصب شده، می‌توانید مسیر دقیق `msedge.exe` یا
`chrome.exe` را در فایل تنظیمات، کلید `chrome_path`، بنویسید.

## سندی که خودش PDF است (برگهٔ پست) — نسخهٔ ۱٫۷

«برگه اطلاعات سفارش»ِ پنلِ ای‌بازار PDF است، نه صفحهٔ وب. از نسخهٔ ۱٫۷،
برنامه پیش از ساختنِ PDF می‌پرسد نشانی خودش PDF هست یا نه. اگر بود،
همان فایل را چاپ می‌کند، بی‌مرورگر. نسخه‌های قدیمی‌تر چنین سندی را
سفید چاپ می‌کنند، پس `agent.py` را با نسخهٔ تازه جایگزین کنید و برنامه
را دوباره اجرا کنید (تنظیمات در `config.json` می‌مانند).

## برگهٔ پست وسطِ کاغذ — نسخهٔ ۱٫۸

در «چاپ مستقیم» تصویر همیشه از گوشهٔ بالا-چپِ کاغذ کشیده می‌شد. اگر
پرینتر اندازهٔ دلخواه را نپذیرد («Microsoft Print to PDF» همیشه Letter است)
یا کاغذش بزرگ‌تر از A5 باشد، برگهٔ پست گوشه می‌افتاد. از نسخهٔ ۱٫۸ کارِ
«برگهٔ پست» (نوع `post_sheet`) وسطِ کاغذِ واقعی کشیده می‌شود. برچسب‌ها و
بقیهٔ کارها مثل قبل از گوشه شروع می‌شوند. برای اینکه برگه کاغذ را پر کند،
کاغذِ همان اندازه (A5 یا A4) را برای پرینتر تعریف کنید.

## برگهٔ استاندارد (A4، A5…) — نسخهٔ ۱٫۹

برچسبِ سفارش حالا می‌تواند یک برگهٔ کامل باشد (در پنل ← برچسب ← «اندازهٔ آماده: برگهٔ A5»).
تا نسخهٔ ۱٫۸ برنامه برای هر کار «اندازهٔ دلخواه» به درایور می‌داد؛ درایورِ خیلی از پرینترهای
کاغذی آن را نمی‌پذیرد و کاغذِ پیش‌فرض (معمولاً A4) را نگه می‌دارد. A5 در سینی وسط می‌نشیند
ولی چاپ از گوشهٔ A4 شروع می‌شد: متن به چپ می‌رفت و بالایش بریده می‌شد.

از ۱٫۹، برای برگه‌های استاندارد (A3، A4، A5، A6، B5، Letter، Legal — عمودی یا افقی)
**کدِ خودِ کاغذ** به درایور داده می‌شود. اگر درایور باز هم کاغذِ پهن‌تری گرفت، برگه وسطِ عرض
چاپ می‌شود و در گزارشِ برنامه هشدار می‌آید. برچسب‌های حرارتی مثل قبل‌اند.

کارهایی که باید بکنید:
- `agent.py` را با نسخهٔ تازه جایگزین کنید و برنامه را دوباره اجرا کنید (تنظیمات می‌مانند).
- در جدولِ پرینترها، برای پرینترِ کاغذی کاغذِ A5 (۱۴۸×۲۱۰) تعریف کنید. اگر هم A4 دارد هم A5،
  «چندکاغذی» را بزنید.
- پرینترِ کاغذی حدودِ ۴ تا ۵ میلی‌متر از لبه را چاپ نمی‌کند. در طراحِ برچسب، کادرِ نقطه‌چینِ
  آبی همین حاشیهٔ امن است؛ متن را داخلش بگذارید.

## اگر برچسب کج یا با اندازهٔ اشتباه چاپ می‌شود

در جدول پرینترها دو ستون تازه هست:

**چرخش** — بعضی پرینترهای حرارتی برچسب را ۹۰ درجه چرخیده می‌کشند، چون
جهت رول کاغذ با جهت پیش‌فرض درایور فرق دارد. اگر برچسب کج چاپ شد، این را
روی ۹۰ یا ۲۷۰ درجه بگذارید. با چرخش، عرض و ارتفاع هم خودکار جابه‌جا
می‌شوند.

**اندازه** — دو حالت دارد:

| گزینه | کار |
|---|---|
| **دقیق** | تصویر دقیقاً به اندازهٔ میلی‌متری تعریف‌شده کشیده می‌شود |
| **جا شود** | تا جایی بزرگ/کوچک می‌شود که در ناحیهٔ قابل چاپ پرینتر بگنجد |

از نسخهٔ ۱٫۱، دیگر تنظیمات پیش‌فرض درایور ویندوز مهم نیست: برنامه برای هر
کار چاپی، اندازهٔ کاغذ و جهت را با DEVMODE به درایور تحمیل می‌کند — دقیقاً
همان کاری که نرم‌افزارهایی مثل NiceLabel می‌کنند. پس مشکل «درایور روی کاغذ
دیگری تنظیم است و همه‌چیز ۹۰ درجه چرخیده چاپ می‌شود» خودبه‌خود حل می‌شود.


## چرا قبلاً یک صفحهٔ سیاه چاپ می‌شد؟

نسخه‌های قبل از ۱٫۲، صفحهٔ برچسب را «عکس» می‌گرفتند. عکس، صفحه را همان‌طور
که در مرورگر می‌بینید ثبت می‌کند: نوار سرمه‌ای بالای صفحه (با متن «اندازهٔ
کاغذ را روی همین ابعاد و مقیاس را روی ۱۰۰٪ بگذارید»)، پس‌زمینهٔ خاکستری و
فاصلهٔ ۶۴ پیکسلی زیر نوار. روی پرینتر حرارتی، آن نوار یک نوار سیاه توپر
چاپ می‌شد و خود برچسب هم به پایینِ کادر رانده و بریده می‌شد.

قواعد `@media print` که این‌ها را پنهان می‌کنند فقط هنگام چاپ اجرا می‌شوند،
نه هنگام عکس‌گرفتن — برای همین در مرورگر درست دیده می‌شد ولی چاپ خراب بود.

از نسخهٔ ۱٫۲، برنامه به‌جای عکس، اول PDF می‌سازد (مرورگر دقیقاً حالت چاپ را
رندر می‌کند) و بعد هر صفحهٔ PDF را با تراکم نقطهٔ خود پرینتر به تصویر تبدیل
و چاپ می‌کند. سه نتیجه دارد:

- نوار و پس‌زمینه و فاصله‌ها اصلاً وجود ندارند.
- اندازهٔ `@page` رعایت می‌شود.
- اگر چند برچسب در یک کار باشد، هرکدام یک صفحهٔ جداگانه می‌شود و همه چاپ
  می‌شوند — قبلاً فقط اولی چاپ می‌شد.

صفحه‌های چاپ سایت هم اصلاح شدند: وقتی ایستگاه چاپ صفحه را باز می‌کند، نوار
راهنما اصلاً در HTML ساخته نمی‌شود.

برای این کار کتابخانهٔ `pypdfium2` لازم است. اگر نصب نباشد برنامه هشدار
می‌دهد و به روش قدیمی برمی‌گردد، پس بعد از به‌روزرسانی حتماً یک بار اجرا کنید:

```
pip install -r requirements.txt
```

## درایور TSPL — کنترل کامل پرینتر حرارتی (ZEC ZP400)

بعضی درایورهای پرینترهای حرارتی چینی (مثل ZEC ZP400) حتی به DEVMODE هم
درست جواب نمی‌دهند. راه قطعی، دور زدن کامل درایور است: برنامه می‌تواند به
زبان خود پرینتر (TSPL — همان زبانی که پرینترهای TSC و کلون‌هایش می‌فهمند)
مستقیم فرمان بفرستد:

```
SIZE 100 mm,150 mm     ← اندازهٔ برچسب
GAP 3 mm,0 mm          ← فاصلهٔ بین برچسب‌ها
DENSITY 8              ← غلظت چاپ
SPEED 4                ← سرعت
BITMAP ...             ← تصویر برچسب، نقطه‌به‌نقطه
PRINT 1,1              ← چاپ کن
```

در این حالت هیچ تنظیمی در ویندوز نمی‌تواند چاپ را بچرخاند یا اندازه را
عوض کند، چون اصلاً از درایور رد نمی‌شود.

**فعال‌کردن:** در جدول پرینترها، ستون «درایور» را برای پرینتر حرارتی روی
«TSPL حرارتی» بگذارید. یک ردیف تنظیمات باز می‌شود:

| تنظیم | توضیح |
|---|---|
| dpi پرینتر | ZP400 و بیشتر مدل‌ها ۲۰۳ هستند (۸ نقطه بر میلی‌متر) |
| فاصلهٔ برچسب‌ها | فاصلهٔ خالی بین دو برچسب روی رول؛ معمولاً ۲ تا ۳ م‌م. رول پیوسته = ۰ |
| غلظت | ۰ تا ۱۵؛ اگر چاپ کم‌رنگ است بالا ببرید |
| سرعت | ۱ تا ۱۲؛ سرعت کمتر = کیفیت بهتر |

بعد «ذخیرهٔ کاغذها» و سپس دکمهٔ «تست» را بزنید — تست هم از همان مسیر
واقعی چاپ می‌رود، پس اگر تست درست درآمد، برچسب‌های واقعی هم درست درمی‌آیند.

اگر بعد از انتخاب TSPL باز هم برچسب چرخیده بود، فقط ستون «چرخش» را روی
۹۰ یا ۲۷۰ بگذارید — چرخش روی خود تصویر اعمال می‌شود و صددرصد جواب می‌دهد.

## تغییرات ذخیره‌نشده

صفحه هر سه ثانیه وضعیت را تازه می‌کند. تا وقتی چیزی را دست‌کاری کرده‌اید
و ذخیره نکرده‌اید، این تازه‌سازی **دیگر فرم را بازنویسی نمی‌کند** و یک نوار
زرد بالای دکمهٔ ذخیره یادآوری می‌کند که تغییرات ذخیره نشده‌اند.


## چند کاغذ برای هر پرینتر

در رابط برنامه، هر پرینتر یک کارت دارد و داخلش فهرست «کاغذها». هر کاغذ اندازه، اغماض،
چرخش، حالت اندازه، درایور (و تنظیمات TSPL) خودش را دارد. «+ افزودن کاغذ» یک کاغذ تازه
می‌سازد؛ با «ذخیرهٔ کاغذها» در `config.json` می‌ماند.

- **هر پرینتر یک کاغذ:** فقط کاغذ پیش‌فرض داخل پرینتر حساب می‌شود. کاغذ فیزیکی را که عوض
  کردید، رادیوی «کاغذ پیش‌فرض» را روی کاغذ تازه بگذارید.
- **چند کاغذ هم‌زمان:** برای پرینتر چندسینی. هر کار کاغذی را که با اندازه‌اش می‌خواند
  (اول پیش‌فرض، بعد بقیه) برمی‌دارد و چرخش/درایور همان کاغذ را اعمال می‌کند. کار بی‌اندازه
  روی کاغذ پیش‌فرض چاپ می‌شود.

تنظیمات قدیمی (یک کاغذ) خودکار به یک کاغذ تبدیل می‌شوند. دکمهٔ «تست» هر کاغذ روی همان
کاغذ چاپ می‌زند و روی تنظیمات ذخیره‌شده کار می‌کند.
